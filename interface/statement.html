Interface System Statement

I designed a cohesive interface system that organizes my sketchbook through a consistent navigation structure and desktop-inspired layout that works across both mobile and desktop screen sizes. The overall design was inspired by older Nintendo DS interfaces and early 2000s phone interfaces because I liked how those systems used simple icon-based layouts that still felt easy to understand and navigate. A lot of those interfaces relied on recognizable icons, categorized menus, and clear interaction states instead of overly complicated visuals, which is something I wanted to incorporate into my own sketchbook design. My homepage acts as a visual index of the sketchbook by organizing links into sections like Sketches, Micro Project, Reading Reflections, and the UI Project. Each section contains icons with labels that resemble app icons which helps users quickly recognize where they want to go while also keeping the interface visually organized. In order to ensure users could easily move between pages without getting lost, I made sure the interface had a persistent hamburger menu on every page. The menu contains links to all major pages in the sketchbook and stays in the same location throughout the interface to create consistency and make navigation more predictable.

While the homepage gives users an overview of the entire sketchbook, the secondary pages are more focused on specific content while still giving users access to the navigation menu at all times. I wanted the system to feel simple and easy to move through without requiring users to memorize where things are located. First, I designed the mobile layouts by focusing on vertical organization, readable spacing, and simplified interaction before expanding the layouts for desktop screens. Since mobile devices have less screen space, I stacked information in a way that keeps the pages readable and easy to navigate. When moving to desktop layouts, I expanded the spacing and visibility of elements instead of completely changing the structure of the interface. This helped maintain consistency between both screen sizes and made the desktop version feel like a natural extension of the mobile layout instead of a completely different design. The icons, captions, and section headings remain visible on both screen sizes to help preserve organization and hierarchy.

The hierarchy system uses consistent typography styles, spacing, and page structures to separate primary content from secondary information across all pages. Larger headings identify page titles and major sections, while smaller text styles are used for captions and supporting information. I also made sure that interaction states are visible through clickable icons and changing page headers depending on which page the user is currently viewing. These interaction cues help users understand where they are in the system and what parts of the interface are interactive. I incorporated Norman's principles through recognizable icon mapping, clear signifiers, visible feedback, and constrained navigation patterns that help reduce confusion. The icon-based layout references older gaming and mobile interfaces that many users are already familiar with, while labels and active states act as signifiers that communicate interaction clearly. Feedback is shown through page transitions, and changing headers. Constraints are also used by simplifying navigation on secondary pages mainly to the hamburger menu, which reduces clutter and keeps the interface more focused on the content of the page the user is on. The design also applies Nielsen's heuristics by maintaining consistency across all page types, supporting recognition over recall, providing visible system status, and giving users clear control over navigation. It also follows several of Shneiderman's Golden Rules by emphasizing consistency, reducing short-term memory load, supporting user control, and providing informative feedback throughout the interface system. This is evident in how each page type shares the same navigation structure, hierarchy logic, and interaction patterns to create a unified and predictable experience across the sketchbook.
